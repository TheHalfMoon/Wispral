# Wispral Master Plan V3 — rebuilt from source evidence

Date: 2026-10-21. Status: **PROPOSED / PLANNING ONLY**. This is the next research-plan version, not a canonical authority transition. No product code, deployment, production STT choice or benchmark leadership is claimed. The active constitution/specification frontier still governs execution.

Wispral becomes the proposed unified voice platform; **WisprSide**, **WisprStudio** and **Klaint** are the final founder-selected product names. The plan maximizes qualified source reuse by extracting/wrapping specific mechanisms, not by combining complete incompatible applications. The sequence remains COPY → ADAPT → INTEGRATE → TEST → IMPROVE. A new implementation requires a written explanation of why the inspected source cannot meet its precise boundary.

This research PR can be reviewed without opening product execution; merging strategy prose must not silently mark any implementation packet READY. Estimated governance preparation: 1–3 engineer-days plus review latency, subject to the actual live frontier.

## W1 — small reuse qualification, no full application fork

After applicable authority opens, qualify three independent seams: pure policy narrowing, pure duration fitting and fake-worker lifecycle. Each gets its exact source/dependency identity, independent positive/negative fixtures, bounded destination and rollback. These can establish extraction viability without a model download, microphone, paid API or a large UI. Narrow the first executable task to one function/contract, not all three at once.

Then qualify Handy recorder/keys and native Windows target delivery separately. Keep text input and copy-only fallback. No backend is production-selected by copying Handy's current transcribe-cpp dependency. Qualify model artifact/consent inventory once before any engine-specific model manager is adopted. Expected small-grain range: 0.5–2 days for a pure seam; 1–3 days for a native/package seam before platform review. These are planning judgments, not measured velocity.

## W2 — first usable release: WisprSide local push-to-talk

Deliver a narrow Windows desktop/CLI-assisted workflow: explicit activation, visible listening state, local qualified ASR, raw and edited text inspection, deliberate delivery to a bound target, explicit failure recovery and keyboard fallback. Start with the simplest qualified speech backend the governed evidence supports; do not score or replace frozen B2 in this plan. Add application formatting/vocabulary only after raw transcription and insertion are stable. Keep optional rewrite off the critical path and never silently invoke cloud fallback.

Developer-agent mode remains an optional capability. First prove a fake ACP peer, then one legitimately available exact-version agent's prompt, permission, cancellation and late-result handling. Qualify a second independent agent before claiming portability. Do not advertise Codex/Claude/Gemini compatibility from initialization/source alone. No voice string is an implicit shell command.

First-release acceptance: clean supported Windows install/uninstall/rollback; no wrong-target delivery, no hidden context capture, no denied-authority action, no unexpected egress in the offline test; raw hypothesis retained; stale/cancelled output refused; accessible keyboard/text path; stable exact native/model artifacts and notices. Numerical performance/accuracy targets are proposed in the [benchmark protocol](../../research/rea/2026-10-21/BENCHMARK_AND_REPLAY_PROTOCOL.md) and must be preregistered before trials. A failed dialect or app fixture narrows the support manifest. Integration estimate after approved scope: 3–6 engineer-weeks, highly dependent on backend/native qualification and review; not a release date.

## W3 — WisprStudio generation and resumable production

Reuse VoiceStudio's fit planner and selected generation/render/resume/project mechanisms. Begin with one exact consent-backed local engine/artifact bundle and a script-to-audio export. Verify cancellation, no network after staging, corruption/OOM/crash recovery and provenance. Add one timeline view and project restore, then long-form chapter/render resumability. Reuse export primitives; include the zero-volume regression exposed by Voicebox source review.

Add dubbing only after single-engine production: local media ingest → preserved source transcript → explicit translation edits → separately qualified alignment/diarization → fit → render → speaker/export checks. Chatterbox multilingual is a qualification candidate; Qwen/CosyVoice, Kokoro, OpenVoice, F5, Piper and Pocket TTS are alternatives for a measured missing capability. Kokoro and Pocket TTS do not establish Arabic support. OmniVoice/Voxtral/F5 weight restrictions remain separate from authorized application code. Do not put incompatible engines in one environment. Refine ST-01…ST-08 from the Studio deep dive as each becomes near-term. Rough integration range: 4–8 engineer-weeks for bounded production, with dubbing/quality studies separately estimated.

## W4 — Klaint text actions, then voice and channels

Start with Parlant's dialogue package plus a restrictive Plan and brokered ToolService. Synthetic knowledge and fake tools first; prove tenant-bound argument resolution, idempotent side effects, unknown-outcome reconciliation, prompt-injection resistance and observable policy denial. Add optional Chatwoot handoff with an ownership epoch and no AI send after takeover. Select one connector from Botpress source and qualify it against a fake API before any legitimate customer sandbox.

Then add one realtime topology, one qualified STT/TTS route and a controlled voice conversation. Compare Pipecat and LiveKit on the actual room/SIP/local requirements rather than duplicating session state. Telephony, outbound calls, CRM production credentials and recordings are separate high-impact grains. Warm transfer must preserve summary/transcript and handle unavailable humans; partial side effects must remain visible. Enterprise acceptance adds tenant isolation, retention, authorization audit, scoped secrets, bounded cost/session duration, chaos/replay fixtures and human review. Initial text/fake-action range: 3–6 engineer-weeks; voice/telephony and enterprise operations require separate measured estimates.

## W5 — evidence-led expansion

Keep distant horizons intentionally coarse: macOS native insertion/accessibility, Linux portals/Wayland, mobile input extensions, hands-free/AEC, richer Studio editing/effects, multilingual long-form dubbing, more connectors, on-prem operations, SDKs and cross-device work. Entry requires a demonstrated user need, qualified donor advantage and independent support/latency/rights evidence. No universal OS support, language count, category leadership, savings or enterprise compliance claim follows from source availability.

Prioritize: (1) authority and wrong-target/tenant/consent failures; (2) first reliable local workflow; (3) recovery and install; (4) held-out Arabic/Gulf and code-switch performance; (5) faster rendering/conversation where measured bottlenecks justify it. Do not build a new foundation model, generic coding agent, IDE, timeline editor, inbox or workflow framework while a suitable donor boundary exists.

## Acceptance and release contracts

Every candidate needs a source/dependency/artifact manifest, applicable license/NOTICE route, exact reviewed head, independent semantic/security review scaled to risk, required mechanical checks and explicit rollback. Once a Rust workspace exists, run fmt, clippy and test with the repository's locked/all-target/all-feature requirements plus touched native/protocol tests. No Cargo command is claimed here because this mission adds no product workspace.

Speech evaluation separates synthetic harness sanity from consent-backed human evidence and frozen public B2. Report all attempted cells, crashes/timeouts, raw/normalized outputs, WER/CER/meaning distortion, p50/p95/first-audio/stop latency, hardware/configuration/RSS/VRAM and uncertainty. Arabic MSA, Saudi/Gulf dialects, English, code-switching, names/numbers/negation, accents, noise and input devices must be stratified. TTS preferences require blinded listeners and consent-backed references. A vendor's marketing figure is not a target result.

Do not ship with denied-action/wrong-target/cross-tenant fixtures failing, stop state misrepresented, unsupported model assets bundled, secrets in logs or offline egress unexplained. Publish a capability manifest with supported OS/app/backend/language combinations and explicit unavailable cells. Rollback disables the adapter and keeps readable project/transcript data; it does not undo externally committed actions. Release authority remains separate from donor selection and planning confidence.
