# 0002. Proposed fork leads and runtime ownership repair

Status: proposed (2026-10-21), not ratified product authority.

## Context

External Opus review #125 validates source evidence but identifies extraction overhead, duplicate owners and missing governance dependencies in #124. Source baselines remain unrun.

## Proposed decision

Refine ADR 0001: retain pinned Handy and VoiceStudio forks conditionally, with baseline/delta registers; Core is contracts, small embedded policy and fixtures. Each runtime retains one process/cancel/inventory authority. Klaint is one Python Parlant service with strict canned responses, tenant retrieval/evaluations, Pipecat only and optional unmodified Chatwoot API. No mandatory Rust daemon or Node/Rails copy.

## Consequences

Retains integrated donor UI/tests/lifecycle, increasing maintenance closure but reducing speculative app reassembly. Faster/safer is a hypothesis until baselines/deltas are measured. Preserve pure guard/policy seams and selective fallback when fork closure fails qualification. Adoption requires the explicit founding-chain amendment and scoped 000G decision; 0001 and historical evidence remain in Git.
