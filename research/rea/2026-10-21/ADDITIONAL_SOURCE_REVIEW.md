# Additional bounded source review

Date: 2026-10-21. Status: research and planning only. Independent source review of two catalog gaps and consistency check of the pillar reports. No product code, package installation, model download, paid inference, microphone capture or native application workflow was run in this review.

## Pocket TTS: a meaningful CPU and streaming alternative

Canonical source is **kyutai-labs/pocket-tts**, revision `cb77ab8561658221d6912cff6e83c09834a70819`. The code LICENSE is MIT. This is an additional candidate, not a replacement for the Studio lead or an empirically selected Arabic engine.

The Python API `TTSModel.generate_audio_stream` at line 650 accepts `stop: threading.Event | None`, splits text, yields decoded sample tensors and checks cancellation before each text chunk. Its `_autoregressive_generation` checks the event before each generation step; a step already running can finish. Decoder and generation threads exist, and the API explicitly says it is **not thread-safe**: use separate model instances for concurrent generation. `generate_audio` collects the streaming tensors into one output, so selecting that convenience method would discard incremental delivery.

The actual upstream `tests/test_streaming_cancellation.py` contains stop-event and client-disconnect tests. It calls `TTSModel.load_model()` and a real voice state, so merely reading or collecting these tests does not qualify cancellation. Both tests remain **NOT_RUN** here. Their source is useful for future integration fixtures, alongside a hung-inference deadline and independent worker-exit proof.

The Rust port offers `TtsModel::generate_audio_stream(stop, on_chunk)` and an autoregressive loop that checks `AtomicBool` per step. A scoped decoder thread is joined before its call returns. The HTTP `ChannelWriter` sets stop when sending to a disconnected response channel fails; this is a concrete cooperative disconnect mechanism, not proof of bounded stop latency or an external-action rollback. The server serializes generation with a mutex. Model/voice acquisition can download URLs or Hugging Face paths, so Wispral must stage admitted artifacts and enforce its network policy around acquisition; source availability does not prove offline operation.

The explicit language list at this pin includes English, French, German, Portuguese, Italian, Spanish and Dutch. **Arabic is absent from the inspected built-in language list.** Community model links in README do not establish official Arabic support, voice rights or measured language quality. README CPU speed/core-count figures are upstream claims, not measurements made on this Windows host. The Rust main uses a default of four tensor threads capped by available parallelism, whereas the README's headline describes two CPU cores; do not copy either as a verified Wispral resource claim.

There is an important identity discrepancy: `pyproject.toml` declares **4.0.0**, while `rust/Cargo.toml` declares **3.3.0**, despite the Rust comment saying versions are kept in step. Always qualify repository SHA, implementation, manifest and artifact together. The Rust dependency is the `gabrieldemarmiesse/xn-ptts` fork pinned to `7efa26973f81bba42cf2ace8da2c1eb9b605d54d`, with `xn 0.2.11`; this closure was not built or audited here. The Rust README warns audio is not bit-identical to Python due to sampler noise and training-checkpoint loading is unsupported.

**Decision:** retain **WRAP / OUT_OF_PROCESS, alternative pending qualification** for optional CPU speech output in Core and WisprStudio. First qualify one exact implementation against Chatterbox/Kokoro for the approved languages and hardware; do not add a second permanent TTS scheduler, model manager or consent store. Reject it as the default Arabic answer at this pin. Required next Grain: exact model/voice/card identity, staged offline acquisition, first-audio and total-time distributions, memory, concurrent-request isolation, disconnect/cancel/hung-worker tests, consent/revocation, and a controlled intelligibility panel. All remain prospective.

Code rights do not establish weight/voice rights. README links a per-voice license catalog; the Rust model's clone fallback tells callers to accept the model host's terms when clone weights are unavailable. No checkpoint or voice card was independently inspected in this bounded addition. Do not infer those assets are covered by the founder's source-code grants.

## Aly: useful cancellation vocabulary, reject whole framework import

The accessible founder-private repository is **TheHalfMoon/Aly**, revision `4a6336ea888d821593a386f63a4506cbb36cf394`, with Apache-2.0 LICENSE and a NOTICE. The package still identifies itself as `orcel-monorepo`, references TheHalfMoon/orcel, and uses `packages/orcel`. Preserve that observed identity/provenance discrepancy; do not mistake it for the separate Rust Orcel donor.

`harness/turn-cancellation.ts` supplies a small `TurnCancelledError`, a cause-chain walker protected against cycles, and `throwIfTurnAborted`. This is reusable error classification and unit-fixture material. It accepts any object with the canonical error name, so classification must **never** authenticate a cancellation receipt, trusted worker identity or permission decision. The actual unit tests deliberately include name-preserving object copies and cyclic causes.

`protocol/cancel-turn.ts` explicitly calls its result cooperative, with `accepted` and `no_active_turn` states. Neither is a stopped state. `settleCancelledTurnStep` traces durable settlement: emit cancelled/waiting, discard pending coordination, remove blocking workflow-tool runs, clear stale input prompts and count token usage once. This is useful recovery behavior to reproduce in independent Core fixtures. It imports the donor's session publication, durable state, harness, workflow and coordination systems; extracting the whole function would pull a large agent runtime into the control plane.

`WORKFLOW_CANCELLATION_CLEANUP_MS` is 30,000 and settlement adds 5,000. Those are upstream implementation budgets, not suitable default speech-interruption targets. `request-envelope.ts` estimates model-visible token cost and persists a request-token state key; its name does not mean it implements the tenant/action/provenance envelope required by Wispral.

**Decision:** **REFERENCE_ONLY** for cancellation/error and stale-prompt/usage fixtures; consider ADAPT of a tiny pure error utility only if the already selected ACP boundary lacks it. Reject entire framework inheritance: it duplicates the selected Parlant dialogue runtime, brings Node >=24, pnpm 12.7.0, model/hosting/workflow coupling and would not replace Core authority. No Aly suite, deployment, durable execution or cancellation experiment was run here. Preserve founder-confirmed code authorization and NOTICE; no donor repository was changed.

## Independent report consistency check

- **WisprSide:** the final evidence record `INK-UNIT-02` contains 17 pure upstream Node tests: 6 target-helper, 8 byte-count recording-guard and 3 synthetic-time repeat-gate cases, exit 0. `INK-UNIT-01` is the same six target tests and overlaps. The report correctly states **17 unique**, not 23. Its raw test text that mentions “real audio bytes” is an upstream case name; the report correctly limits the fixture to byte counts. This supports no native target security, microphone, recognition, keyboard or latency claim.
- **WisprStudio:** the probe helper reports eight named synthetic cases: ordinary fit, overflow fit, mismatched parallel arrays, thread-local cancellation scope/restore, pre-cancelled scope rejection, queued cancellation, running coroutine cancellation and unknown job. Recorded result matches those outputs. This is not eight upstream suite tests, nor any model/native/GPU cancellation proof. The report correctly says no audio inference or quality measurement. Preserve that distinction when aggregating across pillars.
- **Klaint:** the report marks full donor suites and end-to-end customer workflows NOT_RUN and separates probabilistic Parlant guidelines from deterministic authority. No runtime performance, tenant-security or comparative superiority result is established by source inspection.
- The source-fit lead decisions are defensible planning judgments. Their missing measured-quality dimension must remain NOT_MEASURED. Public homepage captures and failed demo playback do not close the requested success/failure/platform competitor workflow coverage.

This review found no blocking contradiction in those three limited claims. It is a source/evidence consistency review, not an independent security or release gate and not a claim that every report line, repository or dependency was audited.
