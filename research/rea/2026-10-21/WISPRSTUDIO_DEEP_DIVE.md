# WisprStudio: source-first generation, editing and dubbing study

Date: 2026-10-21. Mission: [Issue #122](https://github.com/TheHalfMoon/Wispral/issues/122). Status: **research/planning candidate; no product source has been transplanted**. Canonical product implementation remains subject to Wispral's existing governance and 000G.

## Decision

Select **VoiceStudio as the lead donor for Studio-specific dubbing, long-form rendering, recovery and editing mechanisms**, imported in small units behind a bounded Python service. Keep Wispral's Rust control and permission boundary outside that service. Use Voicebox as the alternative generation/story implementation and UX comparison; do not inherit two generation databases, queues or renderers. Select one engine worker per dependency family, rather than combining incompatible model environments. Chatterbox Multilingual is the first Arabic-capable TTS **qualification candidate**, Kokoro is the smaller preset-voice English qualification candidate, and Qwen3-TTS is the voice-design/clone alternative. These are source-fit choices, **not measured audio-quality or production-model winners**.

The first Studio reuse packet should be VoiceStudio's `fit_planner.py`, not a new timeline algorithm. Its dependency closure is the Python standard library, its exact source was executed on synthetic non-audio cases, and its upstream has named numerical/golden fixtures. Later donor modules bring broader dependencies and need their own narrowly scoped packets.

## Evidence and scope

- [studio-source-evidence.json](studio-source-evidence.json) records 14 pinned repositories, 159 acquired source/manifest/test/license/document files, 29 explicitly inspected mechanisms, 11 official model cards, Git blob identities, SHA-256 values and source anchors. Acquisition alone is not a claim that every line of every file was reviewed.
- [studio_mechanism_probe.py](studio_mechanism_probe.py) and [its results](studio-mechanism-probe-results.json) reproduce bounded behavior of unchanged VoiceStudio and Voicebox modules using synthetic non-audio fixtures. Eight named cases cover fit, overflow, malformed parallel arrays, cancellation scope restoration, pre-cancelled scope rejection, queued cancellation, running coroutine cancellation and unknown jobs.
- Full donor applications, TTS inference, speaker cloning, audio quality, GPU behavior, native inference cancellation and complete upstream suites: **NOT_RUN**. No model weights, private voices or media were downloaded. Source execution is not application REA. The platform methodology and REA evidence must retain that distinction.
- Upstream test-path counts are discovery heuristics, not test coverage. For example `melspec.py` and Demucs `spec.py` were falsely matched by a broad filename heuristic. The named tests below are actual paths, with execution status stated separately.
- Latency, intelligibility, fidelity, resource usage, subjective preference and shipping reuse percentage are **NOT_MEASURED**. Upstream comments and model-card comparisons remain upstream claims.

## What the source actually does

### VoiceStudio: reconstruct the pipeline, not its marketing headline

1. `backend/services/dub_pipeline.py::ingest_pipeline` accepts local media or an optional URL branch, emits preparation events, validates media/audio streams, creates temporary PCM outputs and atomically replaces completed files. The inspected extraction creates separate 16 kHz mono ASR and 44.1 kHz stereo separation inputs; this avoids treating an ASR-resampled source as the full-quality background. This is source behavior, not an independently verified fidelity result. First adoption excludes the URL/cookie/downloader branch, which adds network and credential handling unrelated to a local-media first release.
2. `backend/api/routers/dub_generate.py::dub_generate` is a large application orchestration route: task state, voice leases, render staging, speaker reference selection, per-language/segment caches and TTS coordination. It is **not** a tiny portable function. Initially wrap the bounded donor service. Only extract smaller internal mechanisms after contract fixtures preserve behavior. Rebuilding a second dubbing orchestrator before testing this one is unjustified.
3. `backend/services/fit_planner.py::plan_fit` consumes source segments and parallel natural synthesized durations. `FitParams`, `SegmentFit` and `FitPlan` make timing decisions explicit. Standard-library arithmetic assigns audio rate, video ratio, timeline position and residual overflow. The inspected pure function rejects mismatched array lengths. Its constants are algorithm policy, not perceptual quality evidence.
4. `backend/services/duration_planner.py::calibrate_cps`, `estimate_natural_duration`, `classify_segments` predict fit before TTS. The optional condensation path calls an LLM through separate modules. Adopt the arithmetic first; retain optional rewrite/translation as an explicit provider action with source and edited text preserved. Do not label heuristic character-rate prediction an Arabic intelligibility benchmark.
5. `backend/services/longform_render.py` is already shared between Stories and Audiobook. `chapter_cache_key`, `segment_cache_key`, `SegmentCache`, `build_ffmetadata`, `build_concat_list`, `build_render_cmd` avoid a new independent book exporter. Adopt local-input restrictions with the builders. Model inference and FFmpeg execution live outside the pure builder boundary.
6. `backend/services/longform_resume.py::build_manifest`, `write_manifest`, `scan_resumable` preserve the render plan across restart, using safe job-id/directory rules and durable file I/O. Do not treat a resumed manifest as proof an old process is running. Its configured output root and atomic persistence helpers are part of the transplant, not incidental imports.
7. `backend/services/model_lifecycle.py::list_loaded`, `unload` and `unload_all` span in-process TTS/ASR and sidecars. Keep one shared model inventory and scheduler across products. `tts_backend.py` is about 4,500 lines at this pin and includes lazy registry/model-specific logic: copying the whole file as Wispral Core would import a second policy system and numerous optional dependencies. Select an adapter, not the entire registry.
8. `backend/services/subprocess_backend.py::SubprocessBackend` exchanges JSON control plus waveform payloads with engine processes, accounts for worker state, receives with deadlines and quarantines/kills unusable workers. `inference_cancellation.py::InferenceCancellation` is a small job-scoped signal; it explicitly distinguishes killable sidecars from in-process native work that must remain accounted for until return. Copy that distinction into Wispral's cancellation contract.
9. `backend/services/model_acceptance.py` fingerprints displayed model terms, invalidates acceptance after terms change and fails closed on unreadable registry state. A local click records acknowledgement, **not** commercial permission. Wispral should preserve model identity/terms records but keep eligibility separate from acknowledgement. The local-folder branch also cannot establish a checkpoint's rights or digest by itself; the caller needs a verified artifact manifest.
10. `backend/api/routers/profiles.py::record_consent`, `attest_consent`, `revoke_consent` provide recorded-consent/attestation state. The source expressly says its own-voice recording is provenance, not a voiceprint check, and that plain local synthesis is not gated by that flag. Wispral's selected consent policy must therefore gate cloning requests and worker jobs itself, including queued requests after revocation. Renaming a donor field `verified_own_voice` must not inflate its assurance.
11. `electron/src/renderer/src/features/dub/dub-draft.ts::restoreDubDraft` validates segment timing/identifiers, removes selected invalid provider output, restores interrupted work as recovery state and avoids pretending stored work is live. `features/projects/project-format.ts::projectSession` and `projectPayload` map saved project state through that sanitizer. These are better early UI reuse units than importing every Electron main-process bridge.

Actual inspected tests include `tests/test_fit_planner.py`, four committed fit JSON fixtures, `tests/test_duration_planner.py`, `tests/test_longform_render.py`, `tests/test_model_acceptance.py`, `tests/test_model_acceptance_asr.py`, `tests/test_profile_consent.py`, `backend/tests/test_subprocess_recv_timeout.py`, `backend/tests/test_tts_backend_lifecycle.py` and `backend/tests/test_model_load_shutdown.py`. Some integrate broad application imports even when the algorithm under test is pure; full upstream suite execution is **NOT_RUN**. The bounded source probe avoids claiming these suites passed.

### Voicebox: useful narrower alternative, with explicit seams

`backend/backends/__init__.py::TTSBackend` is a Python `Protocol` with `load_model`, `create_voice_prompt`, `combine_voice_prompts`, `generate`, `unload_model`, `is_loaded`. `ModelConfig` describes model identity, auxiliary repositories, language list and feature flags. It provides a useful mapping reference for a typed worker contract, but importing this module also installs Hugging Face compatibility patches. Do not import that side effect into the Rust trust boundary.

`backend/services/generation.py::run_generation` resolves an engine, loads it, builds a voice prompt, invokes `generate_chunked`, persists generated/retried/new-take output, applies optional effects and updates history. `backend/utils/chunked_tts.py::split_text_into_chunks` protects paralinguistic bracket tags and contains English abbreviation and CJK punctuation rules. It does not establish Saudi/Gulf dialect support or language-safe rewriting. These are useful implementations, but should not run alongside a separate VoiceStudio generation/history queue.

`backend/database/models.py` defines `VoiceProfile`, `ProfileSample`, `Generation`, `GenerationVersion`, `Story`, `StoryItem`, `Project`, effects and output channels. `StoryItem` includes start time, track, trims and volume. These are real timeline data models, not evidence of complete video dubbing parity. `StoryTrackEditor.tsx::ClipWaveform` uses a muted media element for waveform visualization while Web Audio handles playback, preventing the visualization player from emitting an independent audio stream. It depends on app hooks, stores and API types; selecting its visual component does not automatically qualify a standalone editor transplant.

`backend/services/task_queue.py::cancel_generation` differentiates queued and running jobs. The source probe observed queued work skipped and a running asyncio coroutine cancelled. It did **not** show that synchronous model computation, a native thread or GPU work stops. The independently required acceptance test is worker-stop acknowledgement plus stale output rejection.

**Export concern requiring a regression test:** `backend/services/stories.py::export_story_audio`, line 1043, converts `float(getattr(item, "volume", 1.0) or 1.0)`. By Python truthiness, a stored volume `0.0` becomes `1.0`. The inspected source therefore creates a mute/export consistency risk. This was not reproduced through the application, and no donor fix was made. Before adopting that exporter, use a zero-volume clip with known nonzero PCM and verify exported silence. The selected architecture uses one Studio renderer and retains this fixture as a cross-implementation test.

### Adjacent processing and editing sources

- **WhisperX:** `whisperx/alignment.py::load_align_model`/`align` provide forced alignment and word/character timestamps; source includes an Arabic wav2vec2 checkpoint mapping. Per-language alignment weights are separately qualified. `tests/test_word_timestamp_interpolation.py` is an actual inspected regression suite. Use its alignment worker after Core produces a transcript; do not add an unrelated second speech-selection policy.
- **pyannote:** `src/pyannote/audio/pipelines/speaker_diarization.py::SpeakerDiarization.apply` is an inspectable segmentation/embedding/clustering/reconstruction boundary. Local community and hosted premium pipelines are distinct in the README. Model access may require accepting its own terms; no token/account use occurred here. Configure `PYANNOTE_METRICS_ENABLED=0` and verify no egress before an offline claim. VoiceStudio's pin requires pyannote `<4.0` while the studied current donor is newer; update compatibility in an isolated adapter rather than silently replacing the historical dependency.
- **Demucs:** `demucs/api.py::Separator.separate_tensor`/`separate_audio_file`, backed by `demucs/apply.py`, provides a bounded stems API. The acquired upstream is archived. Its source is reusable, but no separation quality or model-artifact commercial clearance was inferred from MIT code. Keep optional and recover to the unseparated original with explicit quality status.
- **FFmpeg:** reuse executable argument adapters and established libraries, rather than writing media codecs. `doc/examples/resample_audio.c` illustrates resampling and `libavfilter/af_atempo.c` exposes the existing tempo implementation. Inspect the actual binary's version, configuration and digest before distribution; `--enable-gpl`, `--enable-version3`, external libraries and `--enable-nonfree` change obligations. A subprocess is a technical boundary, not a claim that license obligations disappear.
- **Audacity:** `au3/libraries/au3-project-file-io/ProjectFileIO.h`, `au3/libraries/au3-project-history/UndoManager.h`, `au3/libraries/au3-track/TimeWarper.h` reveal substantial project/undo/track machinery coupled to the editor. They are useful comparison references but importing the whole C++ application is disproportionate to the first Studio timeline. Prefer VoiceStudio's existing edit/project mechanisms; add an Audacity export or explicit interoperable file format only if demanded by real workflows.
- **F5-TTS:** `src/f5_tts/api.py::F5TTS.infer` delegates reference preprocessing, diffusion inference and vocoder output. Its `infer/utils_infer.py` already supplies those implementations, so a new diffusion engine would be unjustified. The released weight card is noncommercial, so this is an optional research alternative rather than the default commercial artifact.
- **Piper:** `src/piper/voice.py::PiperVoice.synthesize` and `libpiper/include/piper.h` provide ONNX/eSpeak generation, audio chunks and alignment metadata. GPL source obligations and per-voice model cards remain distinct. It is a useful low-resource alternative when a qualified voice meets the language and quality requirement; a C ABI declaration alone is not native build/ABI proof on Windows.
